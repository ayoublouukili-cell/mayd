# Langues et thèmes

Les traductions publiques sont centralisées dans `src/lib/i18n/catalog.ts`. Les textes français constituent des clés partagées de type gettext : une même clé est réutilisée dans les pages, les libellés accessibles, les formulaires et les démonstrations. `Text` traduit les chaînes au rendu, `useT` traduit les attributs et les messages, et `Count` gère les décomptes. Les noms de marques, les identifiants et les URL restent inchangés. Les valeurs des options de formulaire restent stables, même lorsque leur libellé est traduit.

Les contenus de production sans traduction connue conservent leur valeur originale. Le code ne traduit pas le texte incorporé dans les photos, les captures ou les vidéos. Aucune traduction n’est écrite en base.

La langue et le thème manuel sont mémorisés dans des cookies de préférence et dans localStorage. Les cookies permettent au serveur de rendre la bonne langue dès la première réponse. Le français est la valeur par défaut. Sans choix manuel, le thème suit le système ; un script dans le head l’applique avant le rendu du corps. Les accès au navigateur sont limités aux effets, aux événements et à ce script, jamais au rendu serveur.

`src/preferences.css` partage les variables du thème et les adaptations RTL. Les maquettes sociales, les médias et les logos conservent leurs couleurs ; les galeries conservent l’ordre de leurs images. Le logo dispose d’un support clair en thème sombre.

Vérifications : `npm.cmd test`, `npx.cmd tsc --noEmit`, `npm.cmd run build`. `scripts/check-ssr-preferences.mjs` vérifie les six rendus serveur. `scripts/check-preferences.mjs` vérifie les six combinaisons dans un navigateur Chromium de test avec diagnostic local sur 9333, sur le serveur défini par `SHOWROOM_URL` (par défaut `http://127.0.0.1:8082`). Ce dernier utilise un profil de test isolé et ferme ce navigateur après les contrôles.
